## Active Rules

### Delegation
- **Sub-agents can stall in plan mode after the parent has exited — fall back to direct edits**: Repeatedly observed 2026-05-07: parent session called `ExitPlanMode` and the harness confirmed `## Exited Plan Mode`, but every fresh `Agent(subagent_type=coder)` invocation that turn re-entered plan mode and returned a plan-only response with `agentId` instead of executing. Three Agent calls burned this way before falling back to direct `Edit` from the orchestrator (which violates the "coder does all code edits" memory rule, but unblocked the user). Rule: if a coder sub-agent returns a plan-only response after the parent is out of plan mode, do NOT loop a fourth retry — apply the edits directly from the orchestrator and note the deviation. The cost of one rule violation is much less than a fourth abandoned sub-agent. (last_triggered: 2026-05-07)
- **Verify a function is LIVE before delegating edits to it**: When briefing the coder agent on which function to modify, grep for the call site and confirm it isn't commented out. I pointed the coder at `_render_all_methods_cdf` in `app/bc/analysis.py:325` — its docstring even said "this function is currently DEAD code", and the call site at `subtabs.py:90` was commented out. The LIVE renderers with the same name live in `app/bc/render_shared.py:267` and `app/bc/render_shared_langer.py:269`. The coder caught this in plan mode and corrected my brief, but it cost a round-trip. Filename and function name are not enough — confirm the call is actually invoked. Pattern: same function name often exists in multiple files (live vs dead vs Langer mirror) — `grep -n 'def funcname\|funcname(' file.py` shows both definition and call sites at once. (last_triggered: 2026-05-04)
- **Verify the live renderer architecture before adding new fields to a result dict**: Before plumbing new data through `runners_cadence.py`'s result dict, check whether the LIVE consumer actually reads from there. The CDF Comparison panel's live renderer (`render_shared.py`) doesn't read `result['best_*_cdf']` — it re-simulates via the cached `_me_cdf_band` helper. Plumbing new fields through the result dict would only feed the dead `analysis.py` mirror. The right place to extend is `_me_cdf_band`'s return type (e.g. switch to a `CDFBandResult` NamedTuple). Pattern: when a panel has both a "stored result" path and a "cached re-sim" path, identify which one is wired to the live UI before designing the data flow. (last_triggered: 2026-05-04)

### Plot Rendering
- **When generating multi-page PDFs with matplotlib, always rasterise + visually inspect every page before declaring done**: `pdf.savefig` does NOT raise on mathtext fallback (literal `$…$` rendering) or on `wrap=True` chopping math segments mid-formula. The error path is "draws fine, looks broken in the rendered PDF only." Workflow: after the PDF is written, run `pdftoppm -r 110 -png file.pdf /tmp/pages/page` and `Read` each PNG. Common failures caught this way: `\bigl`/`\bigr` (mathtext subset, see E052), `wrap=True` with embedded `$math$` (see E053), missing-glyph fallbacks for unicode in `mathtext.fontset='cm'`, axis text overflowing the figure bounds. (last_triggered: 2026-05-07)
- **Never blindly drop a leading axis with `arr[0]`**: When reducing a likelihood/posterior array from N-D to (N-1)-D, walk over `range(arr.ndim)` and squeeze ONLY axes whose `shape == 1`. Loop until `arr.ndim == len(grids)`. Then assert each remaining axis matches its named grid length. The cadence_dsilva branch in `app/bc/render_shared.py` did `p_arr[0]` for years to "drop the logPmax axis", but when `n_logPmax > 1, n_sigma == 1` it dropped the WRONG axis → `best_vals['logPmax']=NaN` → best-fit CDF rendered via broken back-compat path with default `BinaryParameterConfig` → user saw a flat CDF at ~0.12 ("this is bullshit"). Same class bit `render_validation.py:_method_best_and_hdi` earlier in Sprint 4 with the marginal-HDI computation. The cadence_langer branch in the same file already has the correct pattern — mirror it. (last_triggered: 2026-04-28; see `memory/feedback_squeeze_axis.md`)
- **Two-namespace string bugs**: When two coexisting namespaces have similar surface forms but different accepted values (here: runner-mode tags `'dsilva'` / `'langer'` vs period-model values `'powerlaw'` / `'langer2020'`), the type system can't catch the confusion — both are `str`. Translate at the data-source boundary, not at every consumer. The boundary is wherever the tag is FIRST decided (e.g. `render_validation.py:57`); from there, only the canonical-form value flows. Three sites broke at once when Sprint 4 swapped `simulate_delta_rv_sample` for the canonical sampler — see E051. Whenever a function accepts a stringly-typed param, its docstring must list the exact allowed values. (last_triggered: 2026-04-28)
- **Don't trust an agent's "all sites updated" claim — read the code**: Phase 6 coder reported "5 CDFs standardized on teal/red", but the user immediately spotted that Panel B was black/blue with linear interpolation. Lesson: when an agent reports a sweep, grep the file for the constants the sweep was supposed to introduce — `_CDF_OBS_COLOR`, `_CDF_FIT_COLOR`, etc. — and confirm every relevant figure in scope picked them up. Cross-check the agent's enumerated sites against an independent grep for hardcoded hex values; gaps surface immediately. The user should never have to be the cross-check. (last_triggered: 2026-04-28)
- **Step line + step band must match (E047)**: Whenever a line uses `line_shape='hv'`, ANY surrounding uncertainty band MUST also step. This applies to the band's `Scatter(line=dict(shape='hv'))` AND the underlying x-grid — a `np.linspace(0, drv_span, 400)` grid will visually look smooth even with `shape='hv'` because each step is sub-pixel. If the band still looks linear after `shape='hv'`, drop the grid to ~50 points. (last_triggered: 2026-04-28; reinforced by Panel B alignment)
- **`PLOTLY_THEME` is hardcoded DARK — spreading it alone does NOT produce A&A-ready plots**: `app/shared.py:171 inject_theme()` always loads `_DARK_PALETTE`, so `PLOTLY_THEME['paper_bgcolor']` is `#1e1e2e` and `font.color` is `#e0e0e0`. An agent instructed to "use PLOTLY_THEME" will ship a dark figure — the A&A-rule and the PLOTLY_THEME-rule were internally contradictory in plots.md until 2026-04-20. When the user wants paper-ready output (white bg, black text, serif), explicitly apply `_AA_OVERRIDES` on top of PLOTLY_THEME (recipe in `.claude/agents/plots.md` and `memory/feedback_aa_journal_style.md`), and explicitly set `annotation_font.color='#000000'` on every `add_annotation` / `add_vline` / `add_hline`. Forbidden on white bg: `#FFFFFF` / `'gold'` / `#FFD700` trace colors (invisible/low-contrast). Residual zero-lines should be `#555555` mid-grey, not `#333333` (too dark-mode-biased). For `make_subplots` figures, override every `xaxisN` / `yaxisN` individually — `**PLOTLY_THEME` spread only touches `xaxis`/`yaxis`. Before declaring a figure done: state the bg color, list every text element + its color, grep the new code for `'white'` / `'#FFFFFF'` / `'gold'`. Triggered when the plots agent produced the validation diagnostic panels on dark bg with invisible white stairs, instead of A&A white-bg with black stairs. (last_triggered: 2026-04-20)
- **A re-simulated plot MUST use the SAME bin_cfg / period_model / cadence_weights as the grid scoring worker**: Whenever a chart/CDF/score is recomputed from grid-best parameters, every input that affects the simulated ΔRV distribution (full `BinaryParameterConfig` — logP_min, eccentricity, mass distribution, q range, **period_model** — and `cadence_weights`) must come from the SAME source the grid used. Building a fresh `BinaryParameterConfig(logP_max=…)` and discarding the rest is a silent fabrication: it produces a CDF that doesn't correspond to ANY grid cell, and a recomputed logL that disagrees with `logL_raw`. Symptoms: top CDF doesn't match the data, model-explorer "logL" disagrees with the heatmap's stored value, user can find an off-grid "better" point that doesn't actually exist on the real surface. Fix: thread the full `bin_cfg` + `period_model` + `cadence_weights` through to every helper that simulates from "best-fit parameters." Store them in the `result` dict at run time so downstream code never has to guess. **Same class bit the MOCK GENERATOR 2026-05-10**: `app/bc/render_validation.py:351-357` built fresh `BinaryParameterConfig` with only `(logP_min, logP_max, period_model, e_model, e_max)` — `q_range` reverted to default `(0.1, 2.0)` while the grid used `(0.1, 4.0)` from the orbital-params widget. Mock distribution silently 0.05–0.09 narrower in CDF than what the Explorer plotted, and the algorithm best-fit drifted from truth by 3.4 logL. Rule extends to mock generation, not just re-sim helpers — ANY `BinaryParameterConfig(...)` construction outside the `wr_bias_simulation` module needs to inherit the user's full orbital-params config (build base from `settings['grid_cadence_*']['orbital']` then `dataclasses.replace` for truth-specific fields). (last_triggered: 2026-05-10)
- **Helper functions that re-simulate must accept ALL physics-affecting params, not a subset**: A re-sim helper like `_me_cdf_band(fb, pi, sigma_s, sigma_m, bin_edges, logPmax=…)` looks complete because it lists all the "interesting" knobs, but if it constructs `BinaryParameterConfig(logP_max=…)` internally, every other config field silently reverts to module defaults. Either (a) accept a full `bin_cfg` object as a parameter, or (b) stop building a `BinaryParameterConfig` inside the helper. Same rule for `period_model` and `cadence_weights`. (last_triggered: 2026-05-10)
- **Step line + step band must match**: Whenever a line uses `line_shape='hv'` (empirical CDFs, step histograms), any surrounding uncertainty band MUST also step. Use two `shape='hv'` traces with `fill='tonexty'` rather than a single `fill='toself'` polygon. A linearly-interpolated polygon under a stepped line produces the visible "median outside band" artifact even though `lo ≤ med ≤ hi` holds at every sample point. See E047 in COMMON_ERRORS.md. (last_triggered: 2026-04-19)
- **First-glance plausibility is not enough**: User caught that the fixed CDFs matched each other but the band-vs-median misalignment was still wrong. Always zoom into rendering details (axis interpolation, step vs linear, clipping) even when the plot "looks right" at a glance. (last_triggered: 2026-04-19)
- **Result-dict completeness contract**: Every grid runner must persist into the result dict EVERY input that any downstream re-sim/score/CDF helper might need to reproduce a grid cell exactly. Currently required: `bin_cfg` (vars(...) dump), `period_model`, `cadence_library`, `cadence_weights`, `sigma_meas`, `bin_edges`, `likelihood_bin_edges`. Missing fields force downstream callers to invent defaults — and that is the bug above. Audit `runners_cadence.py:480-496` and `runners_cadence_langer.py` whenever a re-sim helper is added. (last_triggered: 2026-04-19)

### Agent Architecture
- **Pipeline constraints ≠ Claude intelligence**: When the agent fails, check if the pipeline is blocking it before blaming the model. Rigid verify→fix loops, scoped prompts, and false-positive gates make the agent "stupid" — not the model. The user wants "let Claude be Claude." (last_triggered: 2026-03-24)
- **Pin-point fixes vs systemic issues**: When the user describes a systemic problem, don't propose a narrow fix. Listen for the broader pattern they're describing. E.g., "why is the agent dumb" → the issue is the pipeline architecture, not one Hebrew path bug. (last_triggered: 2026-03-24)

### UI/Webapp
- **Save/load field names must match exactly**: When adding settings persistence, the field name used in `sm.save(['path', 'field'], ...)` MUST match the field name used in `defaults.get('field', fallback)`. Different naming conventions between save and load (e.g., `nsim` vs `n_sim`, `distA` vs `dist_A`) cause silent persistence failures — settings appear to save but don't reload. Always audit every save/load pair. (last_triggered: 2026-04-06)
- **No hard limits on number inputs**: User explicitly requested no min/max constraints on `st.number_input` widgets. Use `step=` for convenience but let the user type any value. Prefer `st.number_input` over `st.slider` or `st.select_slider` for configuration values. Sliders only for instant-feedback exploration (e.g., playground distribution shape). (last_triggered: 2026-04-06)

### Paper / LaTeX
- **Math-mode contamination cluster — silent killer of A&A unit/value macros**: When unit macros (`\kms`, `\Msun`, `\Lsun`, `\Zsun`, `\Mdot`) embed raw `$...$` toggles in their definitions, calling them inside an existing math expression toggles OUT of math mode mid-expression → tight, font-shape-shifted, "glued" rendering. Always use `\ensuremath{...}` not raw `$...$` in macro definitions. Sister pattern: when a macro ends in `\xspace` (e.g. `\fbincorr → TBD\xspace`) and is used as `\fbincorr^{+\fbinerrup}_{-\fbinerrdn}`, the super/subscripts bind to `\xspace` not the macro → atom binding malformed → "T B D" math-italic with mis-attached errors. Always wrap such macros in `{}` for proper atom grouping: `${\fbincorr}^{+\fbinerrup}_{-\fbinerrdn}$`. Both bugs render as the visually identical "small text glued together with no spaces" symptom. Found in 8 sites in `paper/main.tex`, `abstract.tex`, `bias_correction.tex`, `results.tex`, `methods.tex`, `conclusions.tex`. (last_triggered: 2026-04-29)
- **`\tablefoot{}` content runs together as small-text blob without `\par` separators**: A&A `aa.cls` typesets `\tablefoot{...}` content in `\small`. Multiple `\tablefoottext{a}{...}\tablefoottext{b}{...}` items WITHOUT `\par` (or `\\`) between them render as one continuous small-text run — exactly matching user's "small text glued together" complaint. Always insert `\par` (or `\par\smallskip`) between `\tablefoottext{}` items. (last_triggered: 2026-04-29)
- **`\input{tables/X}` is silently optional — missing it means `\ref{tab:X}` renders as `??`**: A populated table file in `paper/tables/` does NOT auto-include itself; the body section that references the table must `\input{tables/foo}` somewhere. Without the include, `\ref{tab:foo}` renders as `??` and the populated table is invisible in the compiled PDF. Always grep `\input{tables/...` whenever a table is added or referenced. (last_triggered: 2026-04-29)
- **Two-stage figure rendering coordination — lock filenames upfront**: When the writer inserts figure environments with `% \includegraphics{plots/NAME.pdf}` (commented) and the plots agent renders PDFs in a separate run, the `NAME.pdf` filename MUST match between the writer's brief and the plots agent's brief. After both agents finish, the orchestrator uncomments the `\includegraphics` lines via `sed` (faster than re-spawning the writer for mechanical uncommenting). Defer figures still keep their commented `\includegraphics` line — the LaTeX compiles cleanly either way. (last_triggered: 2026-04-29)
